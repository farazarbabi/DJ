# DJ Tools Command Reference

This file summarizes the current repo command surface and the options that matter for normal operation, debugging, and maintenance. The unified `dj` command is the default entry point; the lower-level commands are useful when you want to run or debug one phase directly.

## Project Summary

| Area | What It Does |
| --- | --- |
| `dj` | Runs the end-to-end local DJ library pipeline: fetch missing tracks, scan/link files, ingest metadata, analyze audio, resolve key/BPM, tag files, make playlists, generate cues, group tracks, and write recommendations. |
| `dj fetch-missing` | Matches Exportify Spotify playlist CSVs against the local library and downloads missing tracks, preferring Soundeo when configured and falling back to YouTube. |
| `dj-tagger` | Runs per-track audio analysis and can write the structured COMMENT tag directly to files. |
| `dj-registry` | Maintains the metadata registry that acts as the source of truth for logical tracks, files, observations, canonical key/BPM, taxonomy labels, and cue rows. |
| `dj-grouper` | Builds grouping features, clusters tracks into DJ-friendly groups, writes group playlists, and computes transition recommendations. |

## Common Output Layout

| Path | Meaning |
| --- | --- |
| `outputs/registry/tracks_master.csv` | Logical track table with canonical identity, key, BPM, taxonomy, tagger features, and review fields. |
| `outputs/registry/files_master.csv` | Physical file table with paths, audio technical metadata, embedded tags, and links to logical tracks. |
| `outputs/registry/source_observations.csv` | Source evidence table for tag, Rekordbox, Songstats, Spotify, local analysis, and manual observations. |
| `outputs/registry/review_queue.csv` | Tracks that need manual review, usually because key/BPM evidence is weak or conflicting. |
| `outputs/registry/reports/` | Generated registry, taxonomy, cue, and export reports. |
| `outputs/groups.csv` | Group assignments generated by `dj-grouper`. |
| `outputs/recommendations.csv` | Directional transition recommendations between grouped tracks. |
| `outputs/playlists/groups_coarse/` | Default half-resolution group playlists for Rekordbox. |
| `outputs/playlists/by_key_coarse/` | Default coarse Camelot-key browsing playlists, ordered by BPM then Camelot key. |
| `outputs/playlists/by_bpm_coarse/` | Default BPM-only browsing playlists, grouped into DJ-friendly tempo brackets and ordered by BPM then Camelot key. |
| `outputs/playlists/by_subgenre_coarse/` | Default coarse subgenre browsing playlists, ordered by BPM then Camelot key. |
| `outputs/playlists/groups/` | Full-resolution group playlists written only with `--fine-playlists`. |
| `outputs/playlists/by_key/` | Full-resolution key playlists written only with `--fine-playlists`. |
| `outputs/playlists/by_subgenre/` | Full-resolution subgenre playlists written only with `--fine-playlists`. |
| `outputs/playlists/spotify/` | One representative `.m3u8` playlist per fetched Spotify CSV from standalone `dj fetch-missing` or the default `dj run` fetch phase. |
| `cache/raw_cache.pkl` | Shared expensive raw analysis cache used by tagger, registry, grouper, and cue analysis. Lives under `<library>/cache/` when running on a real library root, under `./cache/` for the default `./files` root. |
| `cache/derived_cache.pkl` | Shared derived analysis cache used to avoid repeated feature derivation; same location rule as `raw_cache.pkl`. |

## Main Workflow: `dj`

| Command | What It Does |
| --- | --- |
| `dj run [PATH ...]` | Runs the full pipeline on one or more audio files/directories, defaulting to `D:\Music` when no path is supplied. |
| `dj fetch-missing [CSV ...]` | Standalone Spotify playlist gap-fill command that downloads missing playlist tracks into the chosen library. |
| `dj vibe-audit [PATH]` | Audits cached vibe score distributions for a library, defaulting to `D:\Music`. |
| `dj export-rekordbox [PATH ...]` | Regenerates the Rekordbox XML collection from an existing registry without a full run. |
| `dj merge-cache DIR [--into DIR]` | Folds another cache directory's `raw_cache.pkl`/`derived_cache.pkl` into the library cache (default `D:\Music\cache`): missing keys are added, duplicates resolved toward the newer file (current tagger version for derived entries), destination files backed up as `*.bak`, source untouched. |
| `dj --version` | Prints the installed `dj-tools` version. |
| `dj -v` / `dj --verbose` | Enables debug-style logging with more detail. |
| `dj -q` / `dj --quiet` | Suppresses normal output and leaves errors only. |
| `dj --no-progress` | Disables registry progress bars, which is useful in logs or scripted runs. |

### `dj run` Options

| Option | What It Does |
| --- | --- |
| `PATH ...` | Audio files or library directories to process; if omitted, the command processes `D:\Music`. |
| `--rekordbox-xml PATH` | Uses a specific Rekordbox XML export instead of auto-detecting the latest XML in the library directory. |
| `--no-songstats` | Skips Songstats metadata enrichment. |
| `--no-tags` | Prevents writing COMMENT tags back to audio files. |
| `--write-key-tag` | Also writes the canonical key to the file's `TKEY` or InitialKey field when supported. |
| `--no-grouping` | Stops after registry/tag/report/playlist work and skips group clustering and recommendations. |
| `--no-clap` | Disables CLAP embeddings during grouping. |
| `--no-essentia` | Skips Essentia key analysis and uses the other available key sources. |
| `-w N` / `--workers N` | Sets the number of analysis workers; the current default is `1`. |
| `--force-extract` | Forces the grouper to re-extract features instead of reusing existing feature cache entries. |
| `--fine-playlists` | Also writes full-resolution `groups/`, `by_key/`, and `by_subgenre/` playlists alongside the default coarse playlists. |
| `--output PATH` | Sets the registry output directory; by default it is `<library>/outputs/registry`. |
| `--no-progress` | Disables registry progress bars for this run. |
| `--fetch-missing [CSV ...]` | Overrides the default Spotify gap-fill input. `dj run` fetches from `<library>/spotify-playlists` by default; pass CSV file(s)/directory here to use those instead. |
| `--no-fetch-missing` | Skips the default Spotify gap-fill phase. |
| `--fetch-format aiff|wav` | Chooses the download format for `--fetch-missing`; the default is `aiff`. |
| `--no-soundeo` | Forces `--fetch-missing` to skip Soundeo and use YouTube-only acquisition. |
| `--force-lookup` | Re-searches tracks previously cached as not found by the fetch workflow. |
| `--check-marked-upgrades` | With `--fetch-missing`, also checks existing `[U]`/`[W]`/`[M]` downloads for Soundeo upgrades. |
| `--cues` | Generates Rekordbox cue points during the run. |
| `--cue-profile v1|v2|v3-default` | Selects the built-in cue generation profile; `dj run` defaults to `v3-default`. |
| `--cue-profile-file PATH` | Loads a custom JSON or YAML cue profile. |
| `--cue-loop-bars N` | Overrides the generated loop length in bars. |
| `--cue-force` | Replaces existing generated `auto_*` cue rows for matched files while preserving manual rows. |
| `--cue-force-analysis` | Recomputes cached cue analysis grids from audio and replaces generated cue rows. |
| `--cue-limit N` | Limits cue analysis to the first `N` matched Rekordbox tracks, which is useful for smoke tests. |
| `--cue-export-xml PATH` | Writes generated cues into a copied Rekordbox XML export at `PATH`. |
| `--cue-export-policy preserve` | Preserves existing Rekordbox markers and skips conflicting generated markers. |
| `--cue-export-policy replace-generated` | Replaces only existing markers that look like they were generated by this tool. |
| `--cue-export-policy replace-empty-slot` | Writes only into empty cue slots; for hot cues this is currently equivalent to preserve behavior. |
| `--cue-export-policy review-only` | Writes reports/statuses without inserting XML cue markers. |
| `--cue-export-dry-run` | Previews cue export statuses without mutating cue rows or XML markers. |
| `--cue-quality-report` | Writes the cue quality report during the run. |
| `--cue-validate-xml` | Validates known Rekordbox marker shapes in the input XML before cue work. |

### `dj fetch-missing` Options

| Option | What It Does |
| --- | --- |
| `CSV ...` | Exportify-style Spotify playlist CSV file(s), or a directory containing CSVs. |
| `--library DIR` | Sets the library directory to check for existing files and download into; the default is `D:\Music`. |
| `--prune-only` | Deletes superseded marked downloads (`[U]`, `[W]`, `[M]`) whose curated unmarked original now exists, then exits without matching or downloading. |
| `--format aiff|wav` | Chooses the download format; the default is `aiff`. |
| `--no-soundeo` | Forces YouTube-only downloads even when Soundeo credentials are configured. |
| `--force-lookup` | Re-searches tracks that were previously cached as not found. |
| `--check-marked-upgrades` | Also checks existing `[U]`/`[W]`/`[M]` downloads for Soundeo upgrades and duration drift; by default present marked files are skipped. |
| `--upgrade-soundeo` | Upgrades playlist tracks already in the library to better Soundeo cuts, then exits: lossless AIFF over `[U]`/`[M]`/`[W]`, Extended over Original, either over a Radio Edit. Marked old copies are deleted; unmarked ones move to `outputs/fetch/replaced/`. Needs Soundeo credentials, never uses YouTube, skips missing tracks, stops at the daily quota, and writes `outputs/fetch/soundeo_upgrade.csv`. Honors `--dry-run` (report only) and `--threshold`. |
| `--forget-cached QUERY ...` | Removes matching not-found cache entries, or clears all entries with `all`. |
| `--threshold FLOAT` | Sets the local-library match score threshold below which a track counts as missing; the default is `0.62`. |
| `--duration-tolerance SECONDS` | Accepts a YouTube result only when its duration is within this many seconds of the Spotify track; the default is `3`. |
| `--max-attempts N` | Tries up to `N` candidate downloads per track before reporting it unmatched; the default is `3`. |
| `--max-duration SECONDS` | Rejects YouTube candidates longer than this duration; the default is `900`. |
| `--min-duration SECONDS` | Rejects YouTube candidates shorter than this duration; the default is `30`. |
| `--dry-run` | Reports what would be matched or downloaded without writing files. |

### `dj vibe-audit` Options

| Option | What It Does |
| --- | --- |
| `PATH` | Library root to audit, defaulting to `D:\Music`. |
| `--output PATH` | Sets the registry output directory, defaulting to `<library>/outputs/registry`. |

## `dj-registry`

Use `dj-registry` when you want to run registry phases directly instead of the unified pipeline.

### Top-Level Commands

| Command | What It Does |
| --- | --- |
| `dj-registry scan [paths ...]` | Scans audio files and updates the registry file table. |
| `dj-registry link` | Links physical file records to logical track records. |
| `dj-registry ingest-rekordbox --xml PATH` | Imports Rekordbox XML metadata as source observations. |
| `dj-registry enrich-isrcs` | Looks up ISRCs through Spotify for tracks that need them. |
| `dj-registry ingest-songstats` | Fetches Songstats metadata and stores it as source observations. |
| `dj-registry analyze` | Runs local audio/key analysis and stores the results in the registry/cache. |
| `dj-registry resolve` | Resolves canonical keys and BPMs from the available evidence. |
| `dj-registry review-queue` | Generates the manual review queue from unresolved or low-confidence evidence. |
| `dj-registry import-reviews` | Imports manual review decisions back into the registry. |
| `dj-registry sync-tags` | Writes canonical registry fields back to file tags. |
| `dj-registry export` | Generates registry reports. |
| `dj-registry taxonomy ...` | Runs the 3-level genre taxonomy workflow. |
| `dj-registry dj-taxonomy ...` | Runs the flat DJ-functional taxonomy workflow used for COMMENT category codes and playlists. |
| `dj-registry cues ...` | Runs cue-point analysis, cue XML export, cue quality reporting, and Rekordbox XML validation. |
| `dj-registry run [paths ...]` | Runs the registry-only pipeline without the unified tool's fetch/group orchestration. |

### Common `dj-registry` Options

| Option | What It Does |

## `dj-tagger`

Use `dj-tagger` for direct per-track analysis or tag writing without running the full registry/grouping pipeline.

| Option | What It Does |
| --- | --- |
| `PATH ...` | Audio files or directories to process, defaulting to `D:\Music`. |
| `-r` / `--recursive` | Recurses into subdirectories when discovering audio files. |

| `--csv PATH` | Exports analysis results to a CSV file. |
| `--json` | Prints analysis results as JSON Lines. |

| `--use-essentia` | Uses Essentia for key detection when installed. |
| `--no-cache` | Skips the analysis cache and forces fresh analysis. |
| `--clear-cache` | Deletes cached tagger results and re-analyzes from scratch. |

## Common Recipes

| Goal | Command |
| --- | --- |
| Run the normal full pipeline on the default library. | `dj run` |
| Run the full pipeline on a specific library with four workers. | `dj run "D:\Music" -w 4` |
| Run analysis and registry work without grouping. | `dj run "D:\Music" --no-grouping` |
| Run without writing tags. | `dj run "D:\Music" --no-tags` |
| Run the full pipeline, including default Spotify gap filling. | `dj run "D:\Music"` |
| Run the full pipeline without Spotify gap filling. | `dj run "D:\Music" --no-fetch-missing` |
| Preview Spotify gap filling without downloading. | `dj fetch-missing --dry-run` |
| Remove superseded marked downloads after curated originals were added. | `dj fetch-missing --prune-only` |
| Preview which library tracks Soundeo could upgrade (no downloads). | `dj fetch-missing --upgrade-soundeo --dry-run` |
| Upgrade library tracks to better Soundeo cuts. | `dj fetch-missing --upgrade-soundeo` |
| Generate cues and a quality report from a Rekordbox XML export. | `dj run "D:\Music" --rekordbox-xml "D:\Music\rekordbox.xml" --cues --cue-quality-report` |
| Preview cue XML export without mutating cue rows or markers. | `dj run "D:\Music" --rekordbox-xml "D:\Music\rekordbox.xml" --cues --cue-export-xml "D:\Music\rekordbox_with_cues.xml" --cue-export-dry-run` |
| Run only the tagger and write tags. | `dj-tagger "D:\Music" --write-tags` |
| Recompute grouper features from scratch. | `dj-grouper run "D:\Music" --force-extract` |
| Generate full-resolution playlists too. | `dj run "D:\Music" --fine-playlists` |
| Run tests. | `python -m pytest` |
| Run playlist-specific tests. | `python -m pytest tests\test_categorical_playlists.py` |
